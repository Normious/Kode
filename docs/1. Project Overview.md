# Project Overview: Kode

**Kode** is a centralized QR code generation and scanning API. One QR engine that
turns any data into a scannable QR code and decodes any uploaded QR image back
into data: generate anywhere, scan anywhere, consistent everywhere.

Part of the **30 Days, 30 Services Challenge** (Day 18, September 2026).
Author: Emmanuel Phiri · Version 1.0.0 · Status: Production Ready.

## Core Purpose

Every modern app eventually needs QR codes: payment references, check-ins, file
links, 2FA enrollment, invoice payment links, product pages. Without Kode each
service installs its own QR library (N inconsistent implementations, no shared
branding, no scan endpoint, no audit trail). Kode solves that with:

- **Generate**: text, URLs, WiFi, vCards, email, SMS, phone, geo, UPI, mobile
  money → QR code
- **Scan**: upload an image containing a QR code → decoded data
- **Customize**: size, colors, error correction, margin, logo embed
- **Multiple formats**: PNG, SVG, DataURI, JSON
- **Smart presets**: `url text wifi vcard email sms tel geo upi momo`, no manual
  string assembly
- **Batch**: up to 50 QR codes per request
- **Multi-tenant**: per-project API keys with own defaults + usage analytics
- **History**: every generation/scan logged with metadata

## Technology Stack

- **Language**: JavaScript (ESM, `type: module`) on **Node.js 20+**
- **Framework**: **Fastify 4** (schema validation, hooks, multipart)
- **QR generate**: `qrcode` (PNG/SVG/DataURI) · **QR decode**: `jsqr` (pure JS)
- **Images**: `sharp` (decode any format → raw RGBA, logo compositing)
- **Database**: **SQLite** via `better-sqlite3` (WAL + FK, zero-config persistence)
- **Auth**: `X-API-Key` header → SQLite lookup (multi-tenant pattern)
- **Deploy**: `npm start`, PM2 (`ecosystem.config.js`), or Docker Compose

## Key Features

| Area | Detail |
| :--- | :--- |
| Formats | PNG, SVG, DataURI, JSON (base64 PNG) |
| Presets | 10 builders with strict format handling |
| Logo embed | Sharp composite, forced `H` error correction |
| Scan | Multi-pass (normal → inverted → upscaled), 4096 px cap |
| Batch | Up to 50 mixed data/preset items per request |
| Tenants | Per-project keys, defaults, isolated history/stats |
| Analytics | Daily rollups + per-preset breakdown |

## Getting Started

```bash
npm install
npm run migrate
npm run seed        # Dobadoba + Gig4Gig API keys
npm start           # http://localhost:4009/health
node scripts/test-local.js   # 19 checks, all green
```

Docker: `docker compose up --build -d` (seed once via
`docker exec kode node src/seed.js`). Details in `6. Operations.md`.

## Architecture Summary

Fastify API → QR engine (`qrcode` / `jsqr` + `sharp`) → SQLite
(`projects`, `qr_history`, `daily_summary`). Every protected route passes
through `X-API-Key` auth; every operation writes an audit row and bumps the
daily rollup. Full breakdown in `2. Architecture Overview.md`.
